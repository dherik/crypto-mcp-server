# crypto-mcp-server

![TypeScript](https://img.shields.io/badge/TypeScript-5.8-blue) ![Node](https://img.shields.io/badge/Node-20+-green) ![License: MIT](https://img.shields.io/badge/License-MIT-yellow)

An MCP (Model Context Protocol) server that connects AI agents (GitHub Copilot, OpenCode, Claude, etc.) to live crypto market data via the [CoinGecko API](https://www.coingecko.com/en/api). No API key required.

Built on the MCP TypeScript SDK v2 and speaks the stateless **`2026-07-28` protocol revision** (no initialize handshake, no session) while remaining compatible with older 2025-era clients.

This server demonstrates **all four MCP primitives**: Tools, Resources, Prompts, and Sampling (via multi-round-trip `input_required` results).

## What it does

### Tools (AI-callable actions)

| Tool | Description |
|------|-------------|
| `get_crypto_price` | Price, market cap, volume, 24h change for any coin |
| `get_top_coins` | Top N coins ranked by market cap |
| `compare_coins` | Side-by-side comparison of two coins |
| `get_market_overview` | Global market cap, BTC dominance, active coins |
| `get_coin_history` | Open/close/high/low over N days |
| `get_ai_insight` | Fetches live data, then asks the client's LLM via a multi-round-trip `input_required` result for a market analysis |

### Resources (AI-readable data)

| Resource URI | Description |
|------|-------------|
| `crypto://market-overview` | Static resource — global market metrics on every read |
| `crypto://coins/{coinId}/profile` | Dynamic resource (URI template) — full coin profile with description, categories, and links. Supports listing (top 10 coins) and autocomplete for `coinId`. |

### Prompts (reusable prompt templates)

| Prompt | Description |
|--------|-------------|
| `analyze-coin` | Fetches live data for a coin, returns a prompt asking the AI to perform structured fundamental analysis |
| `compare-report` | Fetches live data for two coins, returns a prompt asking the AI for a detailed comparison report |

### Example prompts for your AI agent

- *"How is ETH doing today?"*
- *"Compare Bitcoin and Solana"*
- *"What are the top 5 coins right now?"*
- *"Give me a market overview"*
- *"What has BTC done in the last 30 days?"*
- *"Give me an AI insight on Bitcoin"* (asks the client's LLM via `input_required`)

## Setup

### 1. Install dependencies and build

```bash
npm install
npm run build
```

### 2. Test with MCP Inspector (recommended before connecting)

```bash
npm run inspector
```

Open http://127.0.0.1:6274 in your browser. Select **stdio** as the transport, point it at `build/index.js`, and try out each tool, resource, and prompt interactively.

### 3. Connect to GitHub Copilot (VS Code)

Create a `.vscode/mcp.json` file in your project root:

```json
{
  "servers": {
    "crypto": {
      "command": "node",
      "args": ["/ABSOLUTE/PATH/TO/crypto-mcp/build/index.js"]
    }
  }
}
```

Open Copilot Chat, select **Agent** mode, and the crypto tools will be available.

### 4. Connect to OpenCode

Add the MCP server to your `opencode.json` config:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "crypto": {
      "type": "local",
      "command": ["node", "/ABSOLUTE/PATH/TO/crypto-mcp/build/index.js"],
      "enabled": true
    }
  }
}
```

The crypto tools are automatically available in your prompts. You can reference them with `use the crypto tool`.

## MCP Concepts Demonstrated

### Tools
The most common MCP primitive. Tools are actions the AI invokes with structured arguments. The AI decides when to call them based on the `description` field. Each tool returns `content` (text or images) back to the AI.

### Resources
Data the AI can browse and read — like GET endpoints. Two flavors:
- **Static**: fixed URI, always available
- **Dynamic**: URI templates with variables, plus `list` (discovery) and `complete` (autocomplete) callbacks

### Prompts
Reusable prompt templates with parameterized arguments. The client invokes them and receives structured messages that guide the conversation. Good for structured analysis workflows.

### Sampling (via input_required)
The server asks the client's LLM to generate text — but in the `2026-07-28` protocol the server cannot push requests to the client (there is no session). Instead, `get_ai_insight` returns an `input_required` result embedding a sampling request; the client answers it with its model's completion and retries the call, and the server returns the final analysis (Multi Round-Trip Requests). Requires a client that supports sampling/LLM routing; the tool falls back to raw data when no answer arrives. Older 2025-era clients are served by the SDK's legacy shim, which pushes a real `sampling/createMessage` over the session automatically.

## Extending this server

### Add a new tool

Create `src/tools/my-tool.ts`:

```ts
import type { McpServer } from "@modelcontextprotocol/server";
import { z } from "zod";
import { geckoFetch } from "../api/coingecko.js";

export function register(server: McpServer) {
  server.registerTool(
    "my_tool",
    {
      title: "My Tool",
      description: "What this tool does (the AI reads this to decide when to call it)",
      inputSchema: z.object({
        param: z.string().describe("Description of the parameter"),
      }),
    },
    async ({ param }) => {
      const data = await geckoFetch(`/some-endpoint?param=${param}`);
      return {
        content: [{ type: "text" as const, text: JSON.stringify(data) }],
      };
    }
  );
}
```

Then import and call `register(server)` in `src/index.ts`.

### Add a new resource

Create `src/resources/my-resource.ts` and use `server.registerResource()` with a string URI (static) or `new ResourceTemplate(...)` (dynamic).

### Add a new prompt

Create `src/prompts/my-prompt.ts` and use `server.registerPrompt()` with an `argsSchema` and a callback that returns `{ messages: [...] }`.

## Notes

- This server uses the **free CoinGecko API** (no key needed, 30 req/min limit). Rate limit errors (HTTP 429) are caught and surfaced as friendly messages.
- `console.error()` is used intentionally for debug logs — `console.log()` would corrupt the stdio JSON-RPC messages.
- All tools are read-only; this server never writes data or makes transactions.
- Coin IDs are sanitized to prevent injection in API URLs.
- The `get_ai_insight` tool asks the client's LLM through an `input_required` (multi-round-trip) result. If the client does not answer, the tool gracefully falls back to returning raw data with a helpful message.
